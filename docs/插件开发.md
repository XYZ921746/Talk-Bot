# 🧩 插件开发文档（Mod）

插件（Mod）用来**扩展 AI 语音助手的能力**：改写对话内容、提供工具调用（function calling）、监听会话事件等。放一个 `.js` 文件进 `mods/` 文件夹就能生效。

## 📁 放置位置

插件放在**项目根目录的 `mods/` 文件夹**（首次启动时自动创建；兼容旧目录 `server/plugins/`）：

```
D:\222\
├── mods\                ← 把插件 .js 文件放这里
│   ├── example-tools.js
│   └── my-plugin.js
├── server\
└── ...
```

**改完插件重启服务端即可加载**；也可以**热重载**（见下文「热重载」章节，无需重启）。网页「设置 → 插件」分栏可查看插件信息并一键启用/禁用（重新进入会话后生效）。

## ✨ 最小示例

```js
// mods/hello.js
export default {
  name: '我的插件',
  version: '1.0.0',
  description: '一句话说明这个插件做什么',
  priority: 0, // 可选：优先级，数值越大越先执行，默认 0
};
```

插件必须 `export default` 一个对象，**`name` 必填**（唯一，用于显示与开关）。

## 🔌 API 完整参考

### 生命周期钩子（hooks）

| 钩子 | 触发时机 | 返回值 |
| --- | --- | --- |
| `onSessionStart(ctx)` | 每次会话（进入聊天/通话）建立时 | 无 |
| `onSessionEnd(ctx)` | 会话结束时 | 无 |
| `onUserText(text, ctx)` | 用户输入后、发给 LLM 前 | 可返回新文本（改写用户消息） |
| `onAssistantText(text, ctx)` | LLM 回复后、展示/合成语音前 | 可返回新文本（改写回复） |
| `onBeforeTTS(text, ctx)` | TTS 合成前 | 可返回新文本（发音纠正、敏感词过滤） |
| `onToolCall(name, args, ctx)` | 工具执行前 | 可返回新参数对象（改写工具入参） |
| `onToolResult(name, args, result, ctx)` | 工具执行后 | 可返回新结果（改写工具输出） |
| `onError(error, ctx)` | 管道出错时 | 无 |

> **文本钩子规则**：返回**非空字符串**才替换原内容，返回空字符串 / `undefined` / 不返回则保持原样。
>
> **错误隔离**：任何钩子抛异常都只会在服务端日志记录，**不会影响其他插件和主流程**。

```js
export default {
  name: '文本处理示例',
  priority: 50, // 数值越大越先执行
  hooks: {
    // 用户说"帮助"时，替换成让 AI 介绍能力的指令
    async onUserText(text, ctx) {
      if (text.trim() === '帮助') {
        return '请用三句话介绍你自己的能力。';
      }
      return text; // 不改动则原样返回
    },
    // 去掉回复里的 Markdown 符号（语音更自然）
    async onAssistantText(text, ctx) {
      return text.replace(/[*_`#]/g, '');
    },
    // TTS 合成前纠正读音（英文→中文谐音）
    async onBeforeTTS(text, ctx) {
      return text.replace(/Python/gi, '派森');
    },
    async onSessionStart(ctx) {
      ctx.log('会话开始，人设:', ctx.persona?.name);
    },
    async onSessionEnd(ctx) {
      ctx.log('会话结束');
    },
  },
};
```

### 插件上下文 `ctx`

| 字段 | 说明 |
| --- | --- |
| `ctx.sessionId` | 当前会话 ID |
| `ctx.persona` | 当前人设对象（`name`/`systemPrompt`/`language`…），无则 `null` |
| `ctx.config` | 当前会话配置（`llm`/`stt`/`tts`/`vad`） |
| `ctx.log(...args)` | 打印日志（带会话前缀，方便调试） |
| `ctx.store` | 会话级存储对象，插件可跨钩子、跨轮次读写（每个会话独立，会话结束即销毁） |

`ctx.store` 用法示例（在会话内记住状态）：

```js
hooks: {
  async onUserText(text, ctx) {
    ctx.store.msgCount = (ctx.store.msgCount ?? 0) + 1;
    ctx.log(`本会话第 ${ctx.store.msgCount} 条消息`);
    return text;
  },
},
```

### 工具调用（tools / handleTool）

给 LLM 注册可调用函数（OpenAI function calling 格式；接入 Anthropic 时自动转换）。适合做**查询、计算、联网**等插件能力。

```js
export default {
  name: '工具示例',
  tools: [
    {
      name: 'get_weather',          // 工具名（唯一）
      description: '查询指定城市的天气',  // 描述，LLM 靠它决定何时调用
      parameters: {                  // 参数 JSON Schema
        type: 'object',
        properties: {
          city: { type: 'string', description: '城市名' },
        },
        required: ['city'],
      },
    },
  ],
  // LLM 决定调用工具时执行这里，返回值给 LLM 组织回复
  async handleTool(name, args, ctx) {
    if (name === 'get_weather') {
      return { city: args.city, weather: '晴', temp: 26 };
    }
    throw new Error('未知工具: ' + name);
  },
};
```

要点：
- `tools` 里每个工具：`name`（必填，唯一）、`description`（必填，写清楚用途和参数）、`parameters`（JSON Schema）
- `handleTool(name, args, ctx)`：`name` 是工具名，`args` 是 LLM 传的参数对象；返回**字符串或对象**（对象自动转 JSON）作为工具结果
- 工具执行出错请 `throw`，插件系统会捕获并把错误返回给 LLM
- 一个插件可以注册多个工具；多个插件的工具会自动合并（重名时高优先级先生效）
- 可配合 `onToolCall` / `onToolResult` 钩子在工具执行前后改写参数/结果（例如做权限校验、结果加工）

## 🔥 热重载（无需重启）

改完插件后，调用热重载接口即可让新代码生效（已建立的会话不受影响，**新建会话生效**）：

```bash
curl -X POST http://localhost:3210/api/plugins/reload
```

返回 `{ ok: true, message: "已重新加载 N 个插件", plugins: [...] }`。适合开发调试时快速迭代插件，不必每次重启服务。

## 🚀 完整示例（时间查询 + 计算器）

```js
// mods/my-tools.js
export default {
  name: '我的工具集',
  version: '1.0.0',
  description: '提供当前时间与数学计算工具',

  hooks: {
    async onSessionStart(ctx) {
      ctx.log('[我的工具集] 会话开始');
    },
  },

  tools: [
    {
      name: 'get_current_time',
      description: '获取服务器当前日期和时间',
      parameters: { type: 'object', properties: {} },
    },
    {
      name: 'calculate',
      description: '计算数学表达式，如 "12*7+3"',
      parameters: {
        type: 'object',
        properties: { expression: { type: 'string' } },
        required: ['expression'],
      },
    },
  ],

  async handleTool(name, args, ctx) {
    if (name === 'get_current_time') {
      return { time: new Date().toLocaleString('zh-CN') };
    }
    if (name === 'calculate') {
      const expr = String(args.expression ?? '').replace(/[^0-9+\-*/().\s]/g, '');
      if (!expr) return { error: '表达式为空' };
      // eslint-disable-next-line no-eval
      const result = Function(`"use strict"; return (${expr});`)();
      return { expression: expr, result: Number(result) };
    }
    throw new Error('未知工具: ' + name);
  },
};
```

## 🧪 调试

- `ctx.log(...)` 的输出会带 `[session xxx]` 前缀打印在服务端控制台
- 插件加载失败会在启动日志显示 `[plugins] 加载失败 ...`，检查语法和 default 导出
- 临时排查：网页「设置 → 插件」看插件是否出现在列表、工具名是否正确

## ❓ 常见问题

**Q: 插件没生效？**
检查：文件在 `mods/` 根目录（不是子文件夹）、`export default` 导出、重启过服务端、网页「插件」分栏里开关是开启状态（重新进入会话生效）。

**Q: 可以放子文件夹吗？**
目前只扫描 `mods/` 第一层的 `.js/.mjs/.ts` 文件。需要子目录支持可以提出。

**Q: 工具和 LLM 的"插件工具"冲突吗？**
不会。系统把所有插件的工具合并后一起发给 LLM，由 LLM 决定调用哪个。

**Q: 插件能访问网络吗？**
能。插件运行在服务端 Node.js 环境，可以 `fetch` 任意接口（比如查天气、调 API）。

## 🎭 关于 Live2D / 视频通话扩展

插件系统预留了扩展空间以支持未来的 Live2D 视频通话等能力：
- 文本/语音钩子可在合成前改写内容，适配虚拟形象口型/表情驱动
- `ctx.store` 可在会话内维护虚拟形象状态
- 工具调用可扩展虚拟形象动作指令（如"挥手""切换表情"）

后续接入 Live2D 时，可通过插件钩子把 LLM 回复/情绪转发给前端 Live2D 渲染层。
